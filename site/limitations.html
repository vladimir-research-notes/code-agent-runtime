Limitations & non-goals

What is true today, and what this project deliberately is not.

status: current as of Milestone 11

Brief explanation

As of Milestone 11 the repository has a package and CLI, docs, website, packaging, CPU-only tests, an environment check and hygiene scanner, a versioned task format, a tool registry with seven core tools, a runtime loop that drives mock/scripted agents over a task, structured run tracing, trace replay/debugging tooling, permission policies and sandbox controls (enforced by default, with output redaction), scoring with evaluation reports (all four scoring methods, a suite runner, and Markdown/HTML output), regression comparison with flakiness analysis (diff two result files into improved/regressed/unchanged/flaky buckets, plus a rerun mode), an optional cost-controlled LLM adapter (a model-backed llm agent behind a hard pre-call budget guard, a response cache, transcript redaction, and a --dry-run cost preview — offline by default via a deterministic fake client, opt-in to a real Claude API run), and a Claude Code trace importer (normalise an external run into this runtime's trace format and score it with the same scorer, in verify or trust mode).

Deeper technical explanation

Known limitations

  • The sandbox is not a jail. A SandboxPolicy is enforced on every agent tool call (allowed/denied paths, command allow/denylist, network flag, runtime/output caps) — see Sandboxing — but it reduces blast radius, it does not contain malicious native code. Command matching is by program name (a renamed binary or absolute path to a copy is not caught); network enforcement is a heuristic denylist (a direct socket open is not blocked); there is no process/namespace isolation; and cpu_seconds is enforced as a wall-clock bound. The hygiene scanner remains a separate commit-time guard.
  • Trace redaction is heuristic. When the sandbox is enabled (the default), command stdout/stderr, file contents, and diffs are scrubbed of credential-shaped strings before they enter a trace — using the same high-precision patterns as the hygiene scanner, so it can miss novel or obfuscated secrets. With --no-sandbox no redaction occurs. The default --trace destination (traces/) is gitignored regardless.
  • Hygiene secret detection is heuristic. High-precision patterns favor avoiding false positives over catching every secret; it can miss novel or obfuscated credentials and is not a guarantee.
  • Hygiene scope is tracked files. Only git ls-files content is scanned by default; bare env/ENV dirs are not treated as virtualenvs. Use --include-untracked to widen scope.
  • Scoring is evidence, not proof. A test_command pass means the suite went green, bounded by its coverage — one shipped task even passes under the null mock agent because its tests do not cover the new behaviour (see the Results caveats). diff_constraint scores scope, not correctness, and ignores Python bytecode caches as build noise; expected_files checks existence/substrings, not semantic equivalence. Glob matching uses fnmatch (* spans /). Runtime is wall-clock and machine-dependent; only verdicts and tool/command counts are deterministic.
  • Small task set. Six tasks make results illustrative, not a benchmark. Regression comparison judges only the pass/fail signal (improved = gained a pass, regressed = lost one); a “0 regressions” result is not a correctness proof. Flakiness needs repeats — two single-run files cannot reveal it — and small repeat counts make it a smoke check, not a flake-probability estimate; the deterministic baseline shows zero flaky keys. Regression/flakiness reports are Markdown + JSON only (no HTML yet).
  • The LLM cost guard is bounded by its inputs. Pricing is approximate published list pricing in a table that must be verified before a paid run (it is overridable, and an unpriced model is refused, not estimated); token counts use a chars/4 heuristic, not a tokenizer — enough to bound the pre-call worst case, not an exact predictor. The guard stops spend; it does not make a model correct.
  • The offline LLM agent is a harness exercise, not model reasoning. Its default fake client replays a task's known-good solution through the model wire format, so an offline run --agent llm “passing” reflects the scripted solution and the plumbing. A real run is opt-in (--allow-paid, the [claude] extra, an API key, a budget) and is intentionally absent from tests and committed results.
  • An imported run is only as trustworthy as its mode. The importer's trust mode scores the source's declared diff/test result — it believes the source. Only verify mode re-derives the verdict, by reconstructing the workspace from the imported after-state over the task fixture and re-running the task's real test command (a test shows a broken change with a forged “tests passed” is caught only in verify). Verify needs the after-state and the task fixture; diff-only / transcript-only imports fall back to trust and say so. Reconstructed diff line-counts are best-effort (matching --numstat for ordinary text changes; verification does not depend on them); snapshots are text-only; verify runs the test command under the tool output/time caps but not the sandbox path/command policy (it is this runtime's own materialisation).
  • Environment assumption. Tests assume python3 3.10+ with pytest; the src/ layout plus conftest.py shim runs the suite without an install.

Non-goals

Not a production-secure sandbox; not a replacement for any commercial coding agent; not a claim of beating commercial agents; not a benchmark leaderboard; not a large-scale paid-API evaluation; not a web product; not a tutorial.
