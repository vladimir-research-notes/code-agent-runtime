Code Agent Runtime

An independent systems/research platform for the runtime infrastructure around coding agents: task setup, tools, permissions, execution, tracing, replay, scoring, regression comparison, and reports.

status: Milestone 8 — scoring & evaluation reports

Brief explanation

Modern coding agents need a runtime, not just a prompt. This project builds the controlled environment that makes coding-agent behavior reproducible, inspectable, and evaluable: versioned tasks, structured tools, permission policies, command execution, trace recording, replay, scoring, and reports.

Deeper technical explanation

A run takes a versioned task and an agent and produces a scored, replayable trace:

task -> workspace -> agent loop -> tools -> tests -> scoring -> report
                         \__ trace recorder captures every step __/

Deterministic mock and scripted agents are first-class so the whole pipeline can be exercised without any model call. Optional, cost-guarded Claude API / Claude Code adapters are added only after the runtime foundations exist.

Current test/result status

CPU-only tests pass (python3 -m pytest -q), including environment, hygiene-scanner, task-format, tool, runtime, tracing, replay, sandbox, scoring, and eval tests. The runtime suite drives the scripted agent from failing tests to passing end to end and confirms the null mock agent leaves it failing; the tracing/replay suites assert a run reconstructs faithfully from its trace; the sandbox suite asserts blocked-vs-allowed and secret redaction. The scoring suite unit-tests every scorer and the suite runner now produces a real multi-agent baseline — see Results. A guard asserts the committed tree is clean.

Open questions / limitations

The runtime enforces a sandbox policy (path/command/network gating, runtime/output caps) and redacts credential-shaped output on every agent tool call, but this is not a production-grade jail: command matching is by program name, network enforcement is a heuristic denylist, and there is no process/namespace isolation. Scoring now produces real verdicts, but a passing test command is evidence, not proof, of correctness and the task set is small — this is not a benchmark leaderboard. See Limitations, Evals, and Sandboxing.
